Written 2026-09-24, as a planning session. **Zero calls were made to write it.** Supersedes the
scattered G scope in `10_corpus_rebuild_and_dense.md` M5 ("fresh transcript last, once") and
`11_chat.md` (the "G" design bullet). Order is **E → G → F**. E closed 2026-09-24

## Why G exists

Every LLM-backed number on record describes a system that no longer ships.
`test_phase02_results_cite-strict-v2-fixA2_2026-09-10.json` and
`judge_phase06_results_gemini-2.5-flash-lite_2026-09-11.json` were generated on **corpus v1 at
`k=3/doc, top_n=6` with the hand-map-only expander**. Shipping is now **corpus v2,
`k=4/doc, top_n=12`, hand map + OOV bridge**. The model now sees twice as many excerpts from a
different corpus. Those files stay valid **as records of what was said on a date**, and say
nothing about the current system. `cross_turn_drift()` has been wired since Phase 10 C and has
**never been measured**, because measuring it needs real generations.

AI prose is opt-in and defaults OFF, so none of this reaches users by default. That's why
E went first. G is still the gate for turning the AI expander on by default at launch, or
recommending it.

## Budget facts (measured, not assumed)

| pool | limit | source |
|---|---|---|
| `gemini-2.5-flash` (generator) | 20/day, 10/min | 429s, 2026-09-09/11 |
| `gemini-2.5-flash-lite` (judge; also failover) | 20/day, 10/min, **separate pool** | Phase 09 step 1 |
| `gemini-embedding-001` | 100 strings/min, daily unknown, embedding-specific metric | E5.5, 2026-09-24 |

* **The "day" is Google's Pacific day.** The daily cap resets at midnight Pacific, which is **08:00
  WAT** (07:00 UTC) while PDT is in force, and 09:00 WAT after early November. A "Day 1 / Day 2"
  below means two resets, not two calendar dates in Lagos.
* **Generator and judge must stay on different models** (`judge_phase06.py` says so on purpose).
  So **no `--failover` on any G generation run**: a failed-over row would be generated by the
  judge model. A daily-cap 429 leaves the row PENDING (never faked), and the run resumes after
  the reset.
* **Reserve ≥ 4 calls per pool per day** for re-runs of a transient failure. A 503 is retried with
  backoff. A per-minute 429 waits its `retryDelay`.

## Steps

### G0 — Code prep (zero quota, one session)
Nothing in G0 may call Gemini. Every script gets a `--dry-run` / `--no-llm` path, and that
path is exercised before G1.
1. **Answer-shape floor (the confirmed Q3 defect: M5, and `09_evidence_and_generation.md`).** In the prompt, require ≥ 2
   claims with ≥ 2 distinct citations when ≥ 2 distinct refs clear the floor. Scope it to Q3's
   class (the judge found Q8 adequate). Bump `PROMPT_VERSION` → **`cite-strict-v3`**, which also
   auto-misses the prompt-keyed cache. The chat prompt gets the same floor and becomes
   `chat-cite-strict-v2`. **The fix lands before G2, so the quota measures what would ship.** The
   2026-09-10 transcript is the "before".
2. **Re-point the judge.** Add `--transcript=` and `--eval=` to `scripts/judge_phase06.py`
   (equals form only, like every script here). Key the checkpoint on the transcript's sha256, so
   a checkpoint can never resume against a different transcript. Keep the old paths as the
   default, so the 2026-09-11 run stays reproducible.
3. **Multi-turn transcript harness**, new `scripts/transcript_chat.py`: 3 conversations × 3 turns,
   authored in G0 from the **`chat_dev`** set (never `chat_test`, which stays blind), including at
   least one legal → follow-up → pronoun turn. It runs `ask(history=...)` exactly as `app.py`
   does, records `cross_turn_drift()` and `verify_citations()` per turn, writes
   `scripts/transcript_chat_<prompt>_<date>.json`, checkpoints after every call, and runs with
   **no failover**. Zero calls on import. It needs `--i-understand-this-spends-quota`.
4. **Freeze commit.** Every G0 change is committed, then all zero-quota harnesses are re-run and
   diffed against `baseline_phaseE_2026-09-24.txt`. The retrieval numbers must be identical,
   because G0 touches only generation. **Nothing that feeds G2–G4 may change after this commit
   until G4 is done**, or the checkpoints straddle two systems.

### G1 — Pre-declare what is measured (zero quota, written before G2)
Write into this file's **Results** before the first call:
* **Phase 02 (G2):** per question: cited? verbatim tag? refusal correct (Q5, R1/R2)? Q3 shape floor
  met? Compared against fixA2 per question. **Reported, not gated**, since n=12.
* **Judge (G3):** `reverse_rel` arbitration, thinness (Q3, Q8), citation dispositions, supplementary
  faithfulness. The **judge result replaces the proxy only where it rules**. Proxy FAILs stay
  recorded as FAIL (`CLAUDE.md`: don't tune the yardstick).
* **Drift (G4):** the count of turns citing a tag that this turn didn't retrieve but an earlier
  turn did. **Declared bar: 0 drifted tags on 9 turns.** Any drift is a defect to fix in the chat
  prompt, never a reason to widen the allowed-tag set. `verify_citations` failures are reported
  separately.
* **The launch question G answers:** is AI prose good enough to recommend, still opt-in? The
  default stays OFF regardless. Changing the default is out of scope for G.

### G2 → G4 — The quota calendar
Record each day's spend in `HANDOFF.md` **before** starting and **after** finishing.

| Pacific day | flash (gen) | flash-lite (judge) | order |
|---|---|---|---|
| **Day 1** | **G2: 12** (reserve 8) | **G3: first 16** by `--limit=16` (reserve 4) | G2 → offline `eval_phase06 --out=scripts\eval_g2.json` → G3 re-dry-run → G3 |
| **Day 2** | **G4: 9** (reserve 11) | **G3 remainder: ≤ 6** (reserve 14) | resume G3 from its checkpoint → G4 |
| **Day 3** | spare | spare | only if a daily 429 or a failure left rows pending |

* **Why the judge is split rather than run whole:** 21–22 calls don't fit in one 20/day pool, and
  failover would break model separation. It's safe to split *because* of G0.2's sha-keyed
  checkpoint and G0.4's freeze. `CLAUDE.md`'s "a half-finished judge run is wasted quota" holds
  only when the judged transcript can change between days, and the freeze prevents that.
* **Why G4 isn't on Day 1:** 12 + 9 = 21 > 20 on flash.
* **Never run G on a day with any other quota use.** E5.5 (2026-09-24) used only the embedding
  metric, so it doesn't count against Day 1. Day 1 still needs a fresh Pacific day, after the
  reset that follows G0's freeze commit.
